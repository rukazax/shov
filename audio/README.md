# Аудиоверсия «Шова» — как это собрано

Озвучка в духе записей 1С-Паблишинг: чтец-рассказчик, отдельные голоса на персонажей, музыкальная подложка с дакингом, звуковые эффекты на сценарные границы и системные строки. Ничего не покупается и не скачивается — голоса синтезируются, музыка и эффекты генерируются кодом.

## Что чем сделано

| Слой | Инструмент | Файл |
|---|---|---|
| Голоса | синтез речи `edge-tts`, 17 ролей | `render.py` |
| Проверка тембров | медиана основного тона по роли | `voice_probe.py` |
| Музыка (4 подложки) | синтез numpy: синусы, шум, огибающие | `gen_beds.py` |
| Эффекты (6) | синтез numpy: колокол, статика, удар, сквозняк, скрип, щелчок | `gen_beds.py` |
| Роботизация системных строк | кольцевая модуляция + эхо | `render.py` |
| Сведение, дакинг, лимитер | numpy | `render.py` |
| Нормализация громкости | замер `loudnorm` + статичная поправка, −20 LUFS | `render.py` |
| Проверка разметки ролей | правила по именам и роду глаголов | `cast_audit.py` |
| Кодек | mp3 96 кбит/с, моно, 44,1 кГц | `render.py` |

## Разметка ролей: `cast/`

Кто говорит каждую реплику — отдельный файл на главу, `cast/chNN.cast.txt`:

```
74	dialogue	hero	А до меня сюда кто-нибудь лазил? – спросил я у вахтёрши.
111	dialogue	babka	Сеня, – вышла она на балкон, – звони Вите.
```

Колонки: номер блока, тип (`dialogue`/`narration`/`system`), роль, текст. Правится **только роль**, остальное — для контекста. Строки на `#` игнорируются.

| Действие | Команда |
|---|---|
| выгрузить разметку из эвристики | `python3 render.py ../BOOK01/ch01.md --dump-cast` |
| применить патч (`номер<TAB>роль`) | `python3 cast_audit.py cast/ch01.cast.txt --apply patch.txt` |
| проверить все главы | `python3 cast_audit.py` |
| посмотреть разбор без синтеза | `python3 render.py ../BOOK01/ch01.md --only-text` |

Если файл `cast/chNN.cast.txt` есть — рендер берёт роли из него и печатает, что исправил. Нет файла — работает прежнее угадывание по ремаркам. Роль вне списка не применяется (опечатка не глушит голос молча).

Правка роли дешёвая: `cache_key` считается от голоса, темпа, тона, громкости и текста, поэтому пересинтезируется ровно тот блок, у которого сменилась роль, а не вся глава.

`cast_audit.py` находит только доказуемое: имя при глаголе речи против роли, род глагола (`сказал` у женской роли), «сказал он» в реплике героя-рассказчика (о себе он сказал бы «сказал я») и «сказал я» у чужой роли. Просто упомянутое имя не считается — «Михалыч же её поставил» говорит Витя, а не Михалыч.

Угадывание по ремаркам ошибается примерно на 40 % реплик: на главах 1–5, размеченных чтением, эвристика разошлась с разметкой в 195 блоках из 488. Поэтому `cast/*.cast.txt` — обязательный этап, а не украшение; автогенерация (`--dump-cast`) годится только как черновик.

Съезд двух собеседников в сплошном диалоге без ремарок механически не виден — такие места надо читать.

## Голоса

Роли в `VOICES` (`render.py`). Родных русских голосов в каталоге два — Dmitry и Svetlana; персонажей различает согласованный сдвиг по темпу и тону. Поверх тембра ложится просодия от знаков и ремарок.

| Роль | Кто это | Голос | Темп / тон |
|---|---|---|---|
| `hero` | Сеня, первое лицо | Dmitry | +1 % / +2 Гц |
| `narrator` | повествование от третьего лица | Dmitry | −2 % / −2 Гц |
| `bocman` | Боцман | Dmitry | −15 % / −16 Гц |
| `mihalych` | Михалыч, начальник участка | Dmitry | −11 % / −11 Гц |
| `grisha` | Гриша, кладовщик | Dmitry | −8 % / −8 Гц |
| `muhin` | Мухин, Аркадий Львович | Dmitry | −5 % / −5 Гц |
| `leytenant` | лейтенант | Dmitry | +5 % / +4 Гц |
| `tehnik` | техник и любой безымянный мужчина | Dmitry | +9 % / +9 Гц |
| `vitya` | Витя | Dmitry | +14 % / +14 Гц |
| `system` | системные строки Согласования | Dmitry | −25 % / −18 Гц + робот-эффект |
| `agrafena` | Аграфена Тихоновна, старуха автолавки | Svetlana | −13 % / −13 Гц |
| `babka` | бабка Сени, Нина Петровна | Svetlana | −8 % / −9 Гц |
| `ganna` | Ганна Фёдоровна | Svetlana | −4 % / −5 Гц |
| `pozharskaya` | Пожарская, Ольга Тимуровна | Svetlana | 0 / −1 Гц |
| `female` | любая безымянная женщина, Юля | Svetlana | +3 % / +2 Гц |
| `lida` | Лида | Svetlana | +8 % / +7 Гц |
| `dasha` | Даша, дочь | Svetlana | +12 % / +11 Гц |

Женская база (`female`, +3 % / +2 Гц) — та, что владелец принял на прослушивании; остальные женские роли сдвинуты вокруг неё с шагом 4–5 Гц.

Голосов меньше, чем людей: безымянные прохожие, вахтёрши, дежурные и курьеры делят `tehnik` / `female`. Это приём, а не недосмотр — но проверять надо, чтобы два таких человека не оказались в одной сцене.

Мультиязычные голоса каталога читают по-русски с акцентом — на слух слышно сразу, в каст они не пошли. Поэтому «ещё голос» — это сдвиг темпа и тона, а не другой тембр.

Проверка, что роли действительно различаются: `python3 voice_probe.py` — синтезирует по реплике на роль и печатает медиану основного тона. Ожидаемый разброс: мужские 106–138 Гц, женские 157–181 Гц, шаг 3–5 Гц между соседями.

Просодия от знака: вопрос — выше и быстрее, `!` — громче, `…` — медленнее, короткая рубленая реплика — суше и ниже, длинный абзац описания — ровнее. Крик и шёпот узнаются по ремарке («заорал», «прошептал», капс).

## Подложки

| Файл | Для чего | Что внутри |
|---|---|---|
| `beds/calm.wav` | бытовые и разговорные сцены | пад на малой терции, дыхание LFO, редкий колокольчик |
| `beds/tense.wav` | Стык, бумаги, угрозы | гул 55 Гц, сердцебиение 68 уд/мин, диссонирующая секунда |
| `beds/action.wav` | побег, погоня, провал | пульс 132 BPM, шумовые тарелки, подъём |
| `beds/seam.wav` | Шов, протечка, чужая геометрия | гул 41 Гц с дрожью, шипение |

Подложка выбирается по тексту главы: считаются слова-маркеры («бег», «погоня» → action; «допуск», «ведомость» → tense; «шов», «край» → seam; иначе calm). Дальше — дакинг: огибающая голоса опускает музыку на речи и поднимает в паузах. Низ подложки срезан на 110 Гц — иначе он гудит в паузах и читается как шум дорожки.

## Порядок сборки

```bash
cd audio
python3 gen_beds.py                 # подложки и эффекты (2 с)
python3 cast_audit.py               # что в разметке вызывает вопросы
python3 voice_probe.py              # роли и замер основного тона
python3 render.py ../BOOK01/ch01.md # одна глава
python3 check_out.py                # длительность, громкость, битрейт

# вся книга одной командой: надзиратель сам берёт главы по порядку номеров и добирает отставшие
STREAMS=8 JOBS=3 ./render_all.sh
```

Порядок жёсткий: свободный поток берёт **самую младшую** несобранную главу, а занятые пропускает по `flock`. Поэтому том растёт по номерам — вторая, третья, четвёртая, — и слушать можно подряд, не дожидаясь последней. Раньше поток забирал «свои» главы по остатку от `STREAMS`, и быстрый поток убегал вперёд: девятая была готова раньше второй. Вернуть прежнее поведение — `render_all.sh.bak-order`.

`render_all.sh` держит метку `out/.cast-rebuild`: дорожка, собранная раньше неё, считается старой и пересобирается, поэтому смена каста или правка просодии запускается просто новой меткой (`touch out/.cast-rebuild`), без ручного `FORCE`.

Долгий рендер гонять только вне `dsh-web` — иначе перезапуск UI (в том числе по OOM) снимает все потоки разом:

```bash
rootdo systemd-run --unit=shov-audio --collect --uid=ka --gid=ka \
  --working-directory="…/audio" --setenv=HOME=/home/ka \
  --setenv=STREAMS=8 --setenv=JOBS=3 --property=MemoryHigh=4G \
  /bin/bash "…/audio/render_all.sh"
```

Кэш синтеза — `audio/cache/`, повторный рендер главы идёт 20–25 секунд: озвучка берётся из кэша, пересобирается только микс.

`JOBS` выше трёх бесполезен: узкое место — не мы, а сервис синтеза, который отбивает новые тексты волнами. Отсюда и правила: таймаут 25 с на запрос, пауза 0,15–0,5 с между повторами, до шести заходов на главу, восемь параллельных потоков на всю книгу. Подробно — в [`VOICES.md`](VOICES.md#подводные-камни).

## Наблюдение

- Ход озвучки: `systemctl status shov-audio`, лог — `journalctl -u shov-audio`. Готовность глав — какие `out/*.mp3` новее метки `out/.cast-rebuild`.
- Windows-бокс синтеза (192.168.88.20:8765, F5-TTS): каждые 13 минут `shov-win-health.timer` запускает `win_health.sh`. Проверка не косметическая — ping, `/health` и настоящий синтез короткой фразы, потому что `/health` отвечает и у живого, но зависшего процесса. Молчит — скрипт перезапускает движок через `C:\tts\restart_f5.bat` (wmiexec, креды в `/etc/shov-win-health.env`, 0640 root:ka) и проверяет заново. Лог — `logs/win-health.log`, по строке на проверку.

## Трудности, которые пришлось разбирать

- **Сервис синтеза отдаёт звук через раз.** `edge-tts` на длинных очередях сыплет `NoAudioReceived` примерно в 30 % случаев, волнами. Отсюда таймаут 25 с, до шести заходов, пауза 0,15–0,5 с, кэш по блокам: повторный рендер главы — 20–25 с, потому что синтез берётся из кэша.
- **Предохранитель душил сам себя.** Считал отказы подряд: при норме 30 % двадцать отказов набегали за десять секунд, рендер уходил спать на две минуты после десяти секунд работы. Теперь считается тишина с последнего успеха: 45 с без звука — пауза 60, 120, 240, 480. Замер: 27 блоков в минуту при четырёх параллельных главах — норма.
- **Роли перепутывались.** Порядок атрибуции жёсткий: имя в ремарке → глагол речи → оклик как адресат → продолжение предыдущего. Проверка — `cast_audit.py`, а тембр — медиана основного тона по роли в `voice_probe.py`.
- **Без каста не было бы и разметки.** 3553 реплики размечены `cast/chNN.cast.txt`; правка роли не требует синтеза, поэтому ошибки видны до того, как сожжён звук.
- **Гул в паузах.** Низ подложки срезан на 110 Гц, пол паузы замеряется отдельно.
- **Windows-бокс врал двухслойно.** Сторож поднимал F5-TTS на порту 8767 вместо сервера озвучки на 8765, а таймер с `OnUnitActiveSec` после таймаута переставал назначать следующий запуск — теперь `OnUnitInactiveSec`. Проверка сторожем не косметическая: ping, `/health` и настоящий синтез короткой фразы.
- **Публикатор падал на себе.** `cd ..` перед git-блоком ломал относительный путь `logs/publish.log`; скрипт умирал на первой записи, `Restart=on-failure` поднимал его шестнадцать раз без единого коммита. Лечится `LOG="$PWD/logs/publish.log"`.
